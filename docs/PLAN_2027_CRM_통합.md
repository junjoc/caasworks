# CaaS.Works CRM 2027 통합 기획 (v1, 2026-10-20, 엔조)

> 2027년 1월부터 구글 시트를 쓰지 않고 CRM 하나로 세일즈·마케팅·경영지원을 운영한다. 남은 10주 동안의 설계와 순서.
> 현황·진단은 `REPORT_2026-10-20_CRM_현황과_2027_통합준비.md`, 화면 규칙은 `DESIGN_RULES.md`.

## 1. 목표와 성공 기준
- 2027-01-01 부터 매출·고객·청구·미납·현장 이슈 관리를 CRM 에서 입력한다. 시트는 읽기 전용 보관
- 성공 기준
  1. 경영지원이 월 매출·세금계산서·수납을 시트 없이 CRM 에서 마감한다 (2026-12 한 달 병행 후)
  2. 세일즈가 견적서를 CRM 에서 만들어 보내고, 수주하면 현장·매출 예정이 자동 생성된다
  3. 마케팅이 채널→리드→도입→매출→광고비 대비를 한 화면에서 본다 (지금 생애주기 화면)
  4. 데이터 건강 화면의 경고가 0건으로 유지된다

## 2. 사용자와 하루
| 사용자 | 매일 보는 것 | 매일 넣는 것 |
|---|---|---|
| 세일즈 (전성환·박성언) | 내 리드, 다음 액션, 도입직전 | 활동 기록, 단계, 견적서 |
| 마케팅 (최한별) | 유입 추이, 채널별 성과, 콘텐츠 | 광고비(외주), 블로그 통계 업로드 |
| 경영지원 (유라예) | 이번 달 청구 예정, 미납 | 월 매출, 세금계산서 발행·수납 |
| 경영 (김종민) | 매출·도입·미납 요약, 연간 비교 | — |
설계 원칙: 한 숫자는 한 사람이 한 곳에 입력. 화면은 "오늘 할 일"이 먼저, 분석은 분석 메뉴.

## 3. 정보 구조 (메뉴)
```
대시보드    역할별 위젯 (오늘 할 일 · 이번 달 요약)
마케팅      캠페인 · 광고 성과 · 콘텐츠 성과          ← 입력
세일즈      보드 · 리스트 · 리드 등록 · 견적서          ← 입력
고객관리    매출 현황 · 과금 고객 · 전체 고객 · 계약    ← 입력
재무관리    청구/계산서 · 미납 · 매입/비용              ← 입력 (납부 관리는 청구서 수납으로 흡수)
운영관리    현장 · 카메라 반출 · 자산 · 재고 · 장비 · 발주
분석        개요 / 마케팅 / 세일즈 / 매출·재무 / 고객 생애주기   ← 보기 전용
모음        사용자 정의 모음 (중요 현장, 효성 체감온도계 …)       ← 신규
VoC/CS · 업무 · 피드백 · 설정
```
제거: 미팅 관리(파이프라인 활동으로 흡수), 납부 관리, 대시보드 "준비 중" 위젯.

## 4. 데이터 구조 (유지하되 규칙을 한 곳에)
```
pipeline_leads ─ customer_id ─▶ customers ─▶ projects ─▶ monthly_revenues
      │                              │             └─▶ (신규) revenue_plans  월 매출 예정 (견적 수주 시 생성)
      │                              └─▶ invoices ─▶ invoice_items / 수납
      └─▶ activity_logs · quotations(고도화) · topic_tags
collections (신규) ─ collection_items (현장/고객/리드 참조 + 모음별 추가 항목 JSON)
```
- 식별 규칙(한 곳, `src/lib/domain/`): 회사 = 고객사 ID → 정규화 회사명. 도입일 = 단계 이력 → 과금 시작일. 매출 = 공급가. 채널 = 화면 분류
- 모든 쓰기는 API 라우트 경유, 감사 로그·백업 유지. 파괴적 작업은 dry-run → 백업 → 반영

## 5. 기능 설계 (신규·보강)

### 5.1 시트 업로드 화면 (설정 › 데이터 반영)
- 매출 현황·고객 LIST·매입매출·미납 파일을 올리면: 비교 보고(신규/변경/삭제 건수, 월별 합계 대조) → "반영" 버튼 → 백업 → 반영 → 검증 결과
- 지금 터미널에서 돌리는 `scripts/sync/*` 를 그대로 서버 API 로 옮김. 2026-12 까지의 병행 기간용

### 5.2 매출 현황 직접 입력
- 현장(프로젝트) 행에 월 칸을 직접 입력 (시트와 같은 격자). 서비스 추가, 현장 복사, 월정액 자동 채움(과금 시작~종료)
- 입력 즉시 저장, 변경 이력, 월 마감 잠금(경영지원이 마감하면 그 달은 잠김, 관리자만 해제)
- 청구서 초안: 마감한 달의 고객별 매출 합계로 청구서 초안 자동 생성 → 세금계산서 발행일·수납 입력

### 5.3 사용자 정의 모음 (컬렉션)
- 누구나 "모음"을 만들고 현장·고객·리드를 담는다 (검색해서 추가, 표에서 체크해 담기)
- 모음별 추가 항목: 텍스트/숫자/날짜/선택 형식의 열을 사용자가 정의 (예: 설치일, 온도계 수량, 담당자)
- 모음 화면: 담긴 항목 표 + 추가 열 + 메모, 원본 데이터(매출·청구·미납 합계) 자동 표시, 엑셀 내보내기, 공유(팀 전체/본인)
- 분석에서 "모음별"로 필터 가능 (예: 효성 모음의 매출 추이)

### 5.4 견적서 고도화 → 수주 → 매출 연동
1. 견적서는 리드·고객·현장에 붙는다. 단가표에서 품목 선택, 수량·기간·할인, 합계·VAT 자동
2. PDF 출력 (회사 양식, 로고·인감·조건 문구), 이메일 발송, 발송이 리드 활동에 자동 기록
3. 버전 관리 (v1, v2 …), 상태: 작성 → 발송 → 수주 / 보류 / 탈락
4. **수주 처리**: 버튼 하나로 현장(프로젝트) + 서비스 + 과금 조건 생성, 월 매출 예정(revenue_plans) 생성, 리드 단계 도입완료
5. 분석: 견적 금액 vs 실제 매출, 견적 전환율, 담당자별 수주율, 품목별 수주율

### 5.5 데이터 건강 (설정 › 데이터 건강)
- 매일 점검: 고객 미연결 도입완료 리드, 중복 의심 고객, 도입일 없음, 같은 달 청구서 중복, 시트에 없는 미납, 발주유형 미입력, 매출 있는데 청구서 없는 달
- 각 항목 클릭 → 해당 목록 → 바로 수정. 경고 수를 대시보드 관리자 위젯에

### 5.6 사이트 트래킹 살리기
- 홈페이지에 `tracking.js` 설치 요청 (개발팀). 설치되면 문의폼 리드에 세션·방문 경로가 자동으로 붙고 레퍼러 12% → 거의 100%

## 7. 저장·성능·비용
- 현재 DB 약 80~100MB (무료 한도 500MB). 가장 큰 테이블은 감사 로그 52MB(7월부터, 월 약 15MB 증가), 매출 6MB, 프로젝트 5MB
- 5년 운영해도 데이터 자체는 수백 MB. 다만 **2027년 통합 전에 Pro 요금제(월 $25) 전환 권장**: 무료는 일일 백업이 없고, 일주일 안 쓰면 프로젝트가 멈추며, 용량 500MB
- 감사 로그는 1년 보관 후 요약(변경 전후 전체 대신 바뀐 칸만 저장)으로 줄임
- 성능 원칙: 집계는 서버, 화면은 결과만. 분석 결과 5분 캐시. 새 테이블마다 인덱스

## 8. 결정 사항 (2026-10-20, 엔조 제안 → 사용자 확인)
1. 시트에서 옮길 입력: 매출 현황, 고객 LIST, 매입매출, 미납, 이슈 탭(모음), 보증금. 카메라 반출은 보류
2. 입력 담당: 리드·활동=세일즈, 고객·과금 조건=세일즈(도입 시)+경영지원(청구 정보), 매출·세금계산서·수납=경영지원, 광고비·블로그=마케팅
3. 모음 예시: 효성 체감온도계, 중요 현장, 미납 관리 중
4. 견적서 순위: 연결+단가표 → PDF → 발송·활동 기록 → 버전 → 수주 전환
5. 모듈: 사이트 트래킹 살림, 미팅·납부 관리 제거, VoC 유지(하단)
6. 지표: 도입률 = 도입 ÷ 전체 리드, 사이트 전환율 = 문의 ÷ 마케팅 사이트 세션, 매출/광고비 = 유입 후 공급가 ÷ 채널 광고비 (첫 유입 채널)
