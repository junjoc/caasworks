# CaaS.Works CRM 디자인 규칙 (v1, 2026-10-20)

> 모든 화면·버튼·작성 폼이 같은 규칙을 따르게 하기 위한 문서. 새 화면은 이 규칙으로만 만들고, 기존 화면은 "적용 순서"대로 맞춘다.
> 레퍼런스: 먼데이닷컴 — 흰 배경, 넉넉한 여백, 색은 상태를 뜻할 때만, 표는 깔끔한 격자.

## 0. 현재 상태 (왜 정리하는가)
- 화면 82개, 그중 1,000줄 넘는 파일 7개 (고객 상세 2,035줄)
- 버튼: 공용 Button 114회 (secondary 93 / primary 1 / ghost 10 / danger 10) + 날것 `<button>` 47개 파일 → 주 동작이 눈에 띄지 않고 모양이 제각각
- 삭제 확인: 브라우저 `confirm()` 18곳 vs 모달 4곳
- 작성 화면: 모달 22곳, 별도 페이지 6곳 — 기준 없이 섞임
- 색: `bg-blue-100`, `bg-green-100` 같은 직접 지정 300회 이상 → 같은 뜻이 다른 색으로
- 안내줄·탭·날짜 범위 같은 반복 요소가 화면마다 손으로 복사됨

## 1. 메뉴 체계
- 상위 메뉴 순서: 대시보드 › 마케팅 › 세일즈 › 고객관리 › 재무관리 › 운영관리 › 분석 › VoC/CS › 업무 › 피드백 › 설정
- 원칙: **입력·운영 화면은 업무 메뉴**(마케팅/세일즈/고객/재무/운영), **보는 화면은 분석 메뉴**. 한 화면이 두 역할을 하면 입력 쪽에 둔다
- 메뉴 이름은 명사 2~5자, "~관리"는 운영 성격일 때만 (현장 관리, 자산 관리). 분석 메뉴 안에는 소제목(마케팅/세일즈/매출·재무/고객 생애주기)
- 하위 메뉴는 한 메뉴에 최대 7개. 넘으면 화면 안 탭으로 내린다
- 안 쓰는 화면은 메뉴에서 뺀다 (주소는 유지). "준비 중" 화면을 메뉴에 두지 않는다

## 2. 페이지 뼈대 (위에서 아래로, 이 순서만)
1. **페이지 헤더** `page-header`: 왼쪽 제목(+ 한 줄 부제), 오른쪽 동작 버튼 최대 3개 + 기간 선택
2. **안내줄** (선택): 이 화면의 집계 기준·데이터 출처를 한두 문장. `InfoBar` 컴포넌트 (파란 바탕, Info 아이콘)
3. **요약 카드** (선택): 최대 5개, 숫자 하나 + 라벨 + 보조 설명. `KpiCard`
4. **필터줄**: 왼쪽 탭(pill) · 오른쪽 셀렉트/검색/체크박스. 한 줄, 좁으면 줄바꿈
5. **본문**: 표 또는 카드 목록 또는 차트. 차트는 표와 같이 두되 차트가 위
6. **상세**: 행 클릭 → 아래에 펼치는 패널(같은 화면에서 비교할 때) 또는 상세 페이지(편집이 있을 때)
- 한 화면에 섹션이 4개를 넘으면 접기(SectionHeader) 사용, 기본 펼침은 2개까지

## 3. 버튼
| 역할 | variant | 어디에 | 예 |
|---|---|---|---|
| 주 동작 (화면당 1개) | `primary` | 헤더 오른쪽 끝, 폼 오른쪽 아래 | 리드 등록, 저장, 업로드 |
| 보조 동작 | `secondary` | 헤더, 필터줄 | GA4 동기화, 내보내기, 콘텐츠 추가 |
| 조용한 동작 | `ghost` | 취소, 닫기, 표 안의 작은 동작 | 취소, 태그 수정 |
| 파괴적 동작 | `danger` | 확인 모달 안에서만 | 삭제, 합치기 |
- 날것 `<button>` 금지. 모양이 필요하면 `Button` 에 variant 추가
- 크기: 헤더·표 안 `sm`, 폼 `md`. 아이콘은 `sm` 에 w-3.5, `md` 에 w-4, 텍스트 왼쪽에 mr-1
- 라벨은 동사로 끝나는 2~4자 ("저장", "동기화", "엑셀 업로드"). 아이콘만 있는 버튼은 `title` 필수
- 삭제·합치기·덮어쓰기는 **반드시 확인 모달** (`ConfirmModal`: 무엇이 어떻게 되는지 한 문장 + danger 버튼). 브라우저 `confirm()` 금지
- 로딩 중 버튼은 `loading` prop (스피너 + 비활성). 두 번 눌림 방지

## 4. 작성·수정 화면
- **모달**: 입력 6칸 이하, 한 번에 끝나는 것 (콘텐츠 추가, 광고 성과 입력, 태그 수정)
- **별도 페이지** (`/new`, `/[id]`): 입력 7칸 이상, 여러 섹션, 첨부가 있는 것 (리드 등록, 고객 등록, 견적서)
- **인라인 편집**: 표의 한 칸을 바로 고칠 때 (URL, 금액, 단계). 포커스가 빠지면 저장, 토스트로 결과
- 폼 레이아웃: 2열 격자, 긴 글은 전체 폭. 라벨 위, 입력 아래. 필수는 라벨 뒤 `*`
- 버튼: 오른쪽 아래 `취소(ghost) · 저장(primary)`. 모달 헤더에 X 닫기
- 저장 결과: 성공 토스트 짧게("저장 완료"), 실패 토스트에 원인("저장 실패: 고객사 ID 중복")
- 자동 채움(채널 추정, 태그 자동 분류)은 값 옆에 "자동" 표시, 사람이 고친 값은 ✎ 표시

## 5. 표
- `table-container` > `data-table` 만 사용. 헤더는 회색 글자 13px, 본문 13px
- 숫자 열은 오른쪽 정렬 + `tabular-nums`, 금액은 천 단위 쉼표, 단위는 헤더에 ("매출 (원)")
- 날짜 열 `whitespace-nowrap`, 긴 텍스트 `truncate` + `title` 로 전체
- 정렬 가능한 열은 헤더에 ArrowUpDown, 합계 행은 `bg-gray-50 font-semibold` 마지막 행
- 행 클릭 = 상세/펼침, 칸 클릭 = 그 값으로 필터(분석 화면). 둘을 한 표에서 섞지 않는다
- 1,000행 제한: 화면이 원본을 직접 읽을 때는 반드시 나눠 읽기. 분석 화면은 서버 집계 API 만 읽는다
- 빈 표는 `EmptyState` (아이콘 + 한 줄 + 다음 행동 버튼)

## 6. 상태·배지·색
- 색은 **뜻**이 있을 때만: 초록=완료·활성·정상, 파랑=진행·정보, 노랑=대기·주의, 빨강=이탈·미납·오류, 회색=기타·비활성
- 배지는 `Badge` + `badge-*` 토큰 클래스만. `bg-green-100 text-green-700` 같은 직접 지정 금지
- 파이프라인 단계 색, 채널 색, 광고 채널 색은 `src/lib/utils.ts` 의 상수 한 곳에서 (STAGE_COLORS, CHANNEL_COLORS). 화면에서 새로 정하지 않는다
- 강조색(primary 파랑)은 주 동작 버튼·활성 탭·링크에만. 카드 전체를 색으로 칠하지 않는다

## 7. 글자·간격
- 페이지 제목 20px/600, 섹션 제목 14px/500, 본문·표 13px, 보조 설명 12px, 캡션 11px. 그 외 크기 쓰지 않는다
- 카드 안 여백 16px, 카드 사이 12~16px, 섹션 사이 24px
- 한 줄 설명은 `text-text-secondary`, 덜 중요한 보조는 `text-text-tertiary`
- 숫자는 항상 `formatNumber`/`formatCurrency`. 날짜는 `YYYY-MM-DD`, 월은 `YYYY-MM`

## 8. 피드백·상태 표시
- 로딩: `Loading` 컴포넌트 (문장 "로딩 중..." 금지)
- 성공/실패: `toast` 만. `alert()` 금지
- 긴 작업(동기화, 업로드): 버튼 `loading` + 끝나면 결과 토스트에 숫자 ("GA4 콘텐츠 123건 · 일별 7,876행 저장")
- 데이터 출처·기준은 안내줄에. 숫자만 덩그러니 두지 않는다

## 9. 용어 (화면 어디서나 같은 말)
| 쓰는 말 | 뜻 | 쓰지 않는 말 |
|---|---|---|
| 리드 | 파이프라인의 문의 1건 | 인바운드, 문의건 |
| 고객사 | customers 의 회사 | 고객, 거래처 |
| 현장 | projects (프로젝트) | 프로젝트명만 단독 |
| 서비스 | 현장에 붙는 상품 (플랫폼, AI CCTV …) | 솔루션, 품목 |
| 매출 (공급가) | VAT 제외 월 매출 | 매출액 |
| 청구액 (VAT 포함) | 세금계산서 금액 | 청구 금액 |
| 수납 / 미납 | 입금 완료 / 발행 후 미입금 | 결제, 납부 |
| 도입 | 단계 "도입완료" | 수주, 전환, 계약 |
| 도입률 | 도입 ÷ 전체 리드 | 전환율, 승률 |
| 유입 채널 / 유입경로 | 리드의 채널 / 그 안의 소스 | 소스, 매체 |
| 소요일 | 유입일 → 도입일 | 리드타임 |
| 외주 블로그 | 팀부스터·인플루언서 바이럴 | 바이럴 |

## 10. 공용 컴포넌트 (이것만 쓴다)
기존: `Button` `Input` `Select` `Textarea` `Modal` `Badge` `Loading` `EmptyState` `DateRangePicker` `DatePicker` `SearchSelect` `DropdownSelect`
추가할 것: `PageHeader`(제목·부제·동작) `InfoBar`(안내줄) `KpiCard`(요약 카드) `Tabs`(pill 탭) `ConfirmModal`(파괴적 확인) `SectionCard`(접히는 섹션) `DataTable`(정렬·합계·빈 상태 포함)

## 11. 반응형
- 기준 폭 1,280px(노트북). 1,024px 에서 사이드바 접힘. 모바일(400px)은 열람 가능하면 충분, 입력은 모달이 전체 폭
- 표는 컨테이너 가로 스크롤, 페이지 자체는 가로 스크롤 금지

## 12. 적용 순서 (기능 변화 없이 모양만)
1. 공용 컴포넌트 7개 추가 + 토큰 정리 (1일)
2. 분석·마케팅 화면 14개 (2일) — 새 규칙으로 만든 화면이 많아 빠름
3. 세일즈(파이프라인 보드·리스트·상세·등록) (2일)
4. 고객·재무(매출 현황, 고객 상세, 청구서, 미납) (3일) — 파일이 커서 쪼개면서
5. 설정·운영 (1일)
6. 날것 `<button>`·`confirm()`·직접 색 지정 0건 확인 (lint 규칙으로 고정)
