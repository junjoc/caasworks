# CaaS.Works CRM 디자인 규칙 (v2 — 심플·빠름·현재 트렌드, 2026-10-20)

> 목표 세 가지: **코드를 줄인다, 화면이 빠르다, 2026년 업무 도구처럼 보인다.**
> 참고 결: **먼데이닷컴의 표 언어** (상태 칸 전체 색, 그룹 색 줄, 담당자 아바타, 태그 칩) + **Linear·Notion의 가벼운 구조** (흰 바탕, 얇은 선, 그림자 없음, 드로어). 먼데이의 기능 범위(12종 뷰·자동화·문서·전면 드래그)는 가져오지 않는다 — 코드와 속도를 잡아먹는 건 겉모습이 아니라 그것이다.
> 지금 CRM 이 몇 년 전 느낌인 이유: 그림자 있는 둥근 카드, 색으로 칠한 요약 타일, 진한 파란 버튼, 회색 배경 블록, 큰 아이콘, 모달 폼. 아래 규칙은 이것들을 전부 뒤집는다.

## 0. 현재 상태 (10/20 코드 조사)
화면 82개 (1,000줄+ 7개) · 버튼 primary 1 / secondary 93 / 날것 `<button>` 47파일 · `confirm()` 18곳 · 모달 폼 22곳 · 색 직접 지정 300회+

## 1. 겉모습 — 7가지로 끝낸다
1. **바탕은 하나.** 페이지도 카드도 `#fff`. 회색 배경 블록(`bg-gray-50/100`) 없음. 구획은 **1px 구분선**과 여백으로만
2. **그림자 없음, 라운드 6px.** 카드 `shadow` 제거. 떠 있는 것(드로어·메뉴·토스트)만 얇은 그림자
3. **색은 뜻.** 글자 회색 3단계 + 강조색 1개 + 상태색 4개(초록 `#00c875`·파랑 `#579bfc`·주황 `#fdab3d`·빨강 `#e2445c`, 먼데이 팔레트). 상태색은 **상태 칸 전체를 칠하고 글자는 흰색** — 그 칸 하나만. 그 밖의 칸·카드·타일은 칠하지 않는다. 그룹(단계·담당자 묶음)은 왼쪽 4px 색 줄 + 색 글자 제목. 태그는 `#태그` 글자색, 담당자는 이니셜 아바타
4. **글자 한 벌.** Pretendard(없으면 Noto Sans KR) 13px 기본, 제목 18px/600, 보조 12px, 숫자는 `tabular-nums`. 크기는 이 넷만
5. **밀도.** 표 행 36px, 셀 좌우 12px, 카드 안 16px, 섹션 사이 24px. 한 화면에 더 많이 보이되 줄 간격이 숨을 쉬게
6. **아이콘은 16px, 얇게, 적게.** 버튼엔 글자만(아이콘 생략 기본). 이모지 금지
7. **주 동작 하나.** 화면 오른쪽 위에 검정(또는 강조색) 버튼 하나. 나머지는 테두리만 있는 조용한 버튼

## 2. 상호작용 — 요즘 도구가 하는 방식
- **드로어(오른쪽 패널)가 기본 상세.** 행을 누르면 목록은 그대로 두고 오른쪽에서 상세가 열린다. 모달은 "확인"처럼 짧은 것에만
- **인라인 편집.** 표 칸을 바로 고친다(단계·담당자·금액·URL). 포커스 빠지면 저장, 저장되면 칸이 잠깐 깜빡
- **⌘K 명령 팔레트.** 회사명·현장·메뉴 검색해서 바로 이동 (전역 검색 대체)
- **스켈레톤 로딩.** 빙글 도는 로딩 대신 자리 모양의 회색 블록. 0.3초 안에 끝나는 건 아무것도 안 보여줌
- **호버에만 보이는 동작.** 행 끝의 수정·삭제는 마우스를 올렸을 때만
- **빈 상태는 한 줄 + 버튼.** 그림 없음
- **토스트는 아래 가운데, 2초.** 실패만 원인과 함께 남김
- 삭제·합치기는 **드로어 안 확인 영역**(빨간 버튼 + 한 문장). 브라우저 `confirm()` 금지

## 3. 코드를 줄이는 규칙
- **공용 컴포넌트 5개만**: `PageHeader`(제목·부제·주 동작·기간) · `Toolbar`(탭·검색·필터 한 줄) · `DataTable`(정렬·합계·빈 상태·스켈레톤 내장) · `Drawer`(상세·폼·확인) · `Field`(라벨+입력+오류). 기존 `Button` `Badge` `Select` 유지, `Modal`은 `Drawer`로 흡수, `EmptyState`·`Loading`·`KpiCard`는 `DataTable`/`PageHeader` 안으로
- **Tailwind 유틸만.** 페이지별 CSS 없음. `globals.css` 는 토큰(색·글자)과 표 기본만 남기고 80줄 이하
- **색·글자는 CSS 변수.** `--fg`, `--fg-muted`, `--line`, `--accent`, `--ok/--warn/--bad`. 화면에서 `bg-blue-100` 같은 직접 지정 금지 (lint 로 막음)
- **한 파일 300줄 이하.** 1,000줄 화면은 목록/드로어/폼으로 나눔
- **집계는 서버.** 화면은 결과 JSON 만 받는다. 차트는 분석 화면에서만 recharts, 목록 화면의 작은 추이는 inline SVG 스파크라인
- **한 화면 한 번 읽기.** 열릴 때 요청 1~2개. 드로어는 열 때만 그 행의 상세를 읽음
- 매일 쓰는 목록(파이프라인·매출·청구)은 **서버 페이지네이션 + 검색**. 전체 행을 브라우저로 내리지 않는다

## 4. 페이지 뼈대 (이 순서만)
```
PageHeader   제목 · 부제 한 줄 · [기간] [보조] [주 동작]
Toolbar      탭 pill │ 검색 │ 필터 셀렉트 │ 체크      ← 한 줄
DataTable    헤더 고정, 숫자 우측, 합계 마지막 행, 행 클릭 → Drawer
Drawer       상세 요약 → 편집 가능한 칸 → 이력/활동 → (맨 아래) 위험한 동작
```
- 요약 숫자가 필요하면 Toolbar 위에 **한 줄 텍스트형 KPI** ("리드 1,287 · 도입 229 · 도입률 17.8%"). 색 칠한 타일 4개 금지
- 안내줄은 부제 한 줄로 흡수. 긴 설명은 제목 옆 ⓘ 툴팁

## 5. 작성 화면
- 기본은 **Drawer 폼**(목록 위에 열림, 저장하면 목록 갱신). 별도 페이지는 견적서처럼 여러 섹션+첨부일 때만
- 2열 격자, 라벨 위 12px 회색, 입력 32px 높이, 필수 `*`. 오른쪽 아래 `취소 · 저장`
- 자동 채운 값은 칸 안에 "자동" 흐린 글자, 사람이 고치면 사라짐
- 저장 성공은 토스트 없이 **칸 깜빡임 + 드로어 닫힘**. 실패만 토스트

## 6. 표
- 행 36px, 글자 13px, 헤더 12px 회색. 세로선 없음, 가로선 `--line` 1px
- 숫자 우측 `tabular-nums`, 날짜 `nowrap`, 긴 글 `truncate` + 툴팁. 합계 행은 굵게, 배경 없음
- 상태 칸은 **칸 전체 색 + 흰 글자** (먼데이 방식). 단계·채널 색 상수는 `src/lib/utils.ts` 한 곳. 그룹 보기(단계별/담당자별)는 그룹 제목 행 + 왼쪽 색 줄
- 정렬은 헤더 클릭(화살표는 활성 열에만). 칸 클릭 = 필터(분석 화면), 행 클릭 = 드로어(목록 화면). 한 표에서 섞지 않음

## 7. 용어 (화면 어디서나 같은 말)
리드 · 고객사 · 현장 · 서비스 · 매출(공급가) · 청구액(VAT 포함) · 수납/미납 · 도입 · 도입률 · 유입 채널/유입경로 · 소요일 · 외주 블로그
(쓰지 않는 말: 인바운드, 거래처, 솔루션, 매출액, 결제, 수주/전환/계약, 전환율/승률, 리드타임, 바이럴)

## 8. 반응형·다크
- 기준 1,280px. 1,024px 에서 사이드바 아이콘만. 모바일은 열람 중심, 드로어는 전체 폭
- 다크 모드: 토큰을 CSS 변수로 두어 **준비만** 하고 2027년 이후 켠다

## 9. 적용 순서 (기능 변화 없이)
1. 토큰·`globals.css` 정리 + 공용 5개 컴포넌트 + Pretendard (1일)
2. 분석·마케팅 14개 화면 (2일)
3. 세일즈: 파이프라인 리스트/보드 → 드로어 상세, ⌘K (3일)
4. 고객·재무: 매출 현황(격자 편집), 고객 드로어, 청구서·미납 (3일)
5. 설정·운영, lint 로 금지 규칙 고정 (1일)
