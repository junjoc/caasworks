# 기획: 분석 통합 + 고객 생애주기 (2026-10-20 합의)

## 목적
- 마케팅 채널로 들어온 회사 한 곳의 시간 축(유입 → 활동 → 도입 → 월별 매출 → 청구/수납)을 한 화면에서 본다.
- 신규 유입 고객이 연간 얼마의 매출을 내는지(코호트), 전환 소요 기간별로 어떤 회사가 얼마를 내는지, 채널별 생애 가치를 본다.
- 흩어진 분석 화면을 "분석" 메뉴 한 곳으로 모은다 (주소·권한은 그대로, 메뉴 위치만).

## 합의한 기준
- 코호트 기준일 = 리드 유입일(inquiry_date). 소요 기간 = 유입일 → 도입일(converted_at)
- 매출 = 공급가(VAT 제외, 매출현황과 동일). 청구/수납은 회사 타임라인에서만
- 같은 회사 리드가 여럿이면 첫 리드가 생애주기의 시작, 이후 리드는 "추가 진행"
- 리드 없는 기존 고객(2024년 이전 거래)은 코호트에서 제외, 회사 타임라인에서 "유입 기록 없음"
- 전환 소요 기간 분석 축: 발주유형(공공/민간), 업종, 서비스 유형(연결된 고객사 프로젝트), 유입 채널, 담당자, 도입가능성
- 집계는 DB(뷰/RPC)에서, 화면은 결과만 받는다. 분석 결과는 몇 분 캐시

## 단계
1. **분석 메뉴 재편** (메뉴만) — 완료 2026-10-20
   - 분석: 개요 / [마케팅] 마케팅 분석·방문자 여정·연간 비교 / [세일즈] 파이프라인 분석·마케팅 리포트·전환 소요 기간 / [매출/재무] 손익 분석 / [고객 생애주기] 유입 코호트
   - 입력·운영 화면(캠페인, 광고 성과, 콘텐츠, 보드/리스트, 견적, 청구/미납/납부/매입)은 원래 메뉴 유지
2. **연결 정비** — 도입완료 리드 ↔ 고객사 자동 연결(고객사 ID → 회사명 정규화), 도입일 역산(pipeline_history → audit_logs → CONTRACT 활동 → 수동). 못 맞춘 건 목록으로 확인
3. **고객 생애주기 화면**
   - /analytics/cohort 유입 코호트: 유입월 × 1·3·6·12개월 누적 매출, 고객 수, 도입 수, 고객당 매출
   - /analytics/conversion 전환 소요 기간: 구간(≤7 / 8~30 / 31~90 / 90+)별 건수·평균·매출 합, 축 선택, 구간 클릭 → 회사 목록
   - 채널별 생애 가치: 채널 → 리드 → 도입 → 매출 합 → 고객당 매출 → 광고비 대비
   - 회사별 타임라인: 유입(채널) → 활동 → 도입 → 월별 매출 → 청구/미납
4. **개요** — 각 분석의 핵심 숫자 카드 + 상세 링크

## 성능 원칙
- 집계는 Postgres 뷰/함수. 브라우저에서 원본 행 합산 금지
- 새 테이블마다 인덱스. 1000행 제한은 나눠 읽기
- 분석 화면 로딩 시간을 콘솔에 기록 (매출현황 `[revenue.load]` 방식)
