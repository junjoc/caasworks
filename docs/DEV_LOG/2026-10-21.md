# 2026-10-21 (수) 개발일지

## 1. CRM 진입·광고 성과·보드뷰 로딩 속도 개선 (38741fd, 3532d91, 90de6d4)

**증상**: CRM 첫 진입, 광고 성과, 보드뷰 클릭 시 로딩이 수 초.

**원인 (크롬 네트워크 측정)**
- Vercel 함수가 미국 동부(iad1)에서 돌고 DB 는 서울 → API 한 번에 왕복 지연. `/api/analytics/lifecycle` 재생성이 로컬 1초 vs 운영 7~12초
- 보드뷰: `pipeline_leads` 를 `select *` 로 5번(각 ~1MB) 내려받음
- 링크 미리 불러오기: 보드 카드 30여 개 + 사이드바 메뉴 40개가 화면마다 RSC 요청을 쏟아냄 (일부 503)
- `useAuth` 가 컴포넌트마다 `users` 를 따로 읽어 한 화면에 같은 요청 6~9번
- 대시보드: 사용자 행을 읽은 뒤 배치 설정을 또 읽는 2단계 직렬
- 광고 성과: 광고 데이터 → 예산 순차 조회

**조치**
- `vercel.json` `regions: ["icn1"]` → 응답 헤더 `x-vercel-id: icn1::icn1` 확인
- 보드뷰 필요한 열만 + 1,000행 단위, 모자라면 중단
- 사이드바·보드 카드 `<Link prefetch={false}>`
- `useAuth` 모듈 캐시 + 구독으로 앱 전체 1회 조회 (loading 은 예전처럼 세션 확인 직후 false)
- 대시보드 배치 설정은 이미 읽은 users 행에서, 광고 성과는 광고·예산 동시 조회

**결과 (운영, 로그인 크롬)**
| 화면 | 데이터 요청 수 | 데이터 완료 | 비고 |
|---|---|---|---|
| 대시보드 | 19 (위젯) | 1.3초 | users 중복 9→1 |
| 보드뷰 | 8 (전 ~45) | 0.9초 | RSC prefetch 30→4, 리드 2배치 |
| 광고 성과 | 8 (전 12+) | 0.8초 | 첫 진입 1회는 6초 — Supabase 측 장애 공지 시간대 |

**남은 한계**: Supabase Free(Nano) 는 조회 하나당 100~400ms 바닥이 있고 가끔 수 초 멈춤(pg_stat_statements max 2~7초). 대시보드 위젯 19개 조회는 서버 집계 API 하나로 묶는 것이 다음 단계. Pro 플랜 권장은 유지.

## 2. 레이아웃 정의 v1 — 화면 유형 5가지 + 실제 데이터 시안 5장

어제 "레이아웃이 엉성하다" 피드백에 따라 코드보다 먼저 배치를 정의. `docs/design/레이아웃정의_v1.html` (아티팩트 https://claude.ai/artifact/E8aCRLYm9yHcBLrMNq445Q).

- 화면 유형 5: 목록·집계·상세·입력·대시보드. 유형마다 배치 수치 / 데이터 배열 / 불러오기 규칙 3칸
- 시안 5장은 오늘 CRM 실제 데이터(파이프라인 리스트 14행, 2026 코호트, 계룡건설산업 생애주기, 리드 등록 폼, 세일즈 대시보드)로 사이드바·헤더까지 포함해 1,280 틀로 렌더링. 치수 라벨은 체크박스로 켬
- 엔조가 먼저 정한 7가지: 틀 하나(200/48/20) · 표는 틀을 채움 · 목록 50행 서버 페이지 · 상세 2:1 · 대시보드 자유 드래그 제거(위젯 3종·프리셋 3) · 입력은 드로어 · 화면당 요청 상한(목록 2·집계 1·상세 1·입력 0·대시보드 1)
- 규칙 요약은 docs/DESIGN_RULES.md 부록 3. 확정 후 코드 순서: 틀 → 목록 API+리스트 → 집계 4화면 → 상세 → 입력 드로어 → 대시보드 API
- 사용자 확인: "전체적으로 좋다". 추가 요청 3건 반영 — ① 보드뷰를 6번째 화면 유형으로(진행 6열 + 접힌 도입완료·이탈, 카드 72 3줄, 열당 30장, board API 1회) ② 리스트 단계 칩 폭 통일(최소 64, 2글자도 4글자 폭) ③ 색은 새로 만들지 않고 v1 12색·단계 매핑 유지 (8색 안은 폐기)
- 색 수정: 신규리드 ↔ 이탈 맞바꿈 — 신규리드 빨강(눈에 띄게), 이탈 회색(묻히게). `stageTone` 한 줄 반영

## 3. 레이아웃 정의 적용 시작 — 집계 3화면 + 전역 틀

- 유입 코호트·채널별 생애 가치·전환 소요 기간을 "집계" 유형으로: 열 비율 고정(월별↔분기별 열 위치 동일), 주 표 2 : 채널 표 1 윗선 맞춤, 월별 12줄, 설명은 ⓘ 기준
- 표 공통: 첫 열이 남는 폭을 먹던 규칙 철회(폭은 내용 비율), 머리 전부 가운데, 숫자 오른쪽·날짜·칩 가운데·글 왼쪽, 상태 칩 최소 64 + 글자 상하좌우 가운데, 선택 행 파란 세로줄 제거
- 전역 틀: 사이드바 200·선 아이콘·현재 메뉴 표시, 헤더 48, 본문 여백 20/16, 페이지 바탕 흰색, 카드 그림자 제거(1px 선). 화면별 개별 수정은 하지 않음
- 회사 생애주기 서비스별 매출을 이전·올해·누적으로 나누는 안은 시안에만 반영(코드는 다음에)
