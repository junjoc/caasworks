## 1. CRM 진입·광고 성과·보드뷰 로딩 속도 개선 (38741fd, 3532d91, 90de6d4)

**증상**: CRM 첫 진입, 광고 성과, 보드뷰 클릭 시 로딩이 수 초.

**원인 (크롬 네트워크 측정)**
- Vercel 함수가 미국 동부(iad1)에서 돌고 DB 는 서울 → API 한 번에 왕복 지연. `/api/analytics/lifecycle` 재생성이 로컬 1초 vs 운영 7~12초
- 보드뷰: `pipeline_leads` 를 `select *` 로 5번(각 ~1MB) 내려받음
- 링크 미리 불러오기: 보드 카드 30여 개 + 사이드바 메뉴 40개가 화면마다 RSC 요청을 쏟아냄 (일부 503)
- `useAuth` 가 컴포넌트마다 `users` 를 따로 읽어 한 화면에 같은 요청 6~9번
- 대시보드: 사용자 행을 읽은 뒤 배치 설정을 또 읽는 2단계 직렬
- 광고 성과: 광고 데이터 → 예산 순차 조회

**조치**
- `vercel.json` `regions: ["icn1"]` → 응답 헤더 `x-vercel-id: icn1::icn1` 확인
- 보드뷰 필요한 열만 + 1,000행 단위, 모자라면 중단
- 사이드바·보드 카드 `<Link prefetch={false}>`
- `useAuth` 모듈 캐시 + 구독으로 앱 전체 1회 조회 (loading 은 예전처럼 세션 확인 직후 false)
- 대시보드 배치 설정은 이미 읽은 users 행에서, 광고 성과는 광고·예산 동시 조회

**결과 (운영, 로그인 크롬)**
| 화면 | 데이터 요청 수 | 데이터 완료 | 비고 |
|---|---|---|---|
| 대시보드 | 19 (위젯) | 1.3초 | users 중복 9→1 |
| 보드뷰 | 8 (전 ~45) | 0.9초 | RSC prefetch 30→4, 리드 2배치 |
| 광고 성과 | 8 (전 12+) | 0.8초 | 첫 진입 1회는 6초 — Supabase 측 장애 공지 시간대 |

**남은 한계**: Supabase Free(Nano) 는 조회 하나당 100~400ms 바닥이 있고 가끔 수 초 멈춤(pg_stat_statements max 2~7초). 대시보드 위젯 19개 조회는 서버 집계 API 하나로 묶는 것이 다음 단계. Pro 플랜 권장은 유지.
