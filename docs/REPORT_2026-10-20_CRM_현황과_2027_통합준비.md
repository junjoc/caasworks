# CaaS.Works CRM 현황 정리와 2027 통합 준비 (2026-10-20)

> 마케팅팀과 함께 CRM 의 구조·기능을 다시 정의하기 위한 자료. 2027년부터 구글 시트를 쓰지 않고 CRM 하나로 운영하는 것이 목표.

## 1. 지금 CRM 에 들어 있는 것

### 데이터 흐름 (현재)
```
문의 (홈페이지 폼 → Slack 자동등록 / 수동 등록)
  → 파이프라인 리드  (채널·유입경로·주제 태그·담당자·단계·도입일)
    → 고객사         (고객사 ID, 타입, 과금방식, 담당자, 청구 정보)
      → 프로젝트(현장) × 서비스
        → 월별 매출 (공급가)            ← 매출 현황 시트 (월 1회 파일 반영)
        → 청구서 / 세금계산서 / 수납    ← 매입매출·미납 시트 (월 1회 파일 반영)
마케팅 : 광고 성과(네이버·구글 자동, 외주 블로그 수기) · 콘텐츠 성과(GA4 + 네이버 블로그 통계) · 방문자 여정(GA4) · 연간 비교(2023~2026 현황표)
분석   : 유입 코호트 · 전환 소요 기간 · 채널별 생애 가치 · 회사 생애주기 타임라인 · 파이프라인 분석 · 마케팅 리포트
```

### 자동으로 들어오는 것 / 사람이 넣는 것
| 자동 | 사람 |
|---|---|
| Slack 문의알림 → 리드 생성, 채널·주제 태그 자동 분류 | 리드 단계·담당자·도입가능성·발주유형 |
| 네이버·구글 광고 성과 (API) | 외주 블로그(팀부스터) 월 비용, 광고별 문의·도입 수기 |
| GA4 방문·블로그 조회 | 네이버 블로그 통계 엑셀 업로드 (월 1회) |
| 리드 ↔ 고객사 연결 (고객사 ID → 회사명) | 매출·고객·청구서 시트 → CRM 반영 (월 1회, 파일 공유) |

### 데이터 연결 상태 (2026-10-20 점검)
| 항목 | 상태 |
|---|---|
| 도입완료 리드 → 고객사 연결 | 97% (229곳 중 222) |
| 도입완료 리드 → 도입일 | 97% |
| 도입완료 고객 → 매출 | 88% (나머지는 시트에 금액 미기재) |
| 청구서 고객 ↔ 매출 고객 | 94% |
| 리드 채널·주제 태그 | 100% |
| 리드 발주유형(공공/민간) | 24% (4월 이후 항목) |
| 리드 레퍼러 | 12% (7월 이후 문의폼만) |
| 매출 있는 고객 중 CRM 리드가 있는 곳 | 42% (2024년 이전 고객은 리드 없음) |
| 쓰이지 않는 모듈 | 사이트 트래킹(0), 견적서(0), 미팅(0), 납부관리(0), VoC(1) |

## 3. 솔직한 진단

- 테이블 구조(리드 → 고객 → 프로젝트 → 매출/청구)는 맞고, 핵심 연결은 이어졌다.
- 다만 "설계됐다"기보다 "쓰면서 자라났다": 같은 규칙이 여러 곳에 흩어져 있었고(회사 식별, 채널, 도입일), 데이터 들어오는 길이 여러 갈래(시트 4종, API, 수기)이며, 화면 파일이 너무 크고(1,000줄+), 만들어 두고 안 쓰는 모듈이 있다.
- **전면 재개발은 권하지 않음.** 지금 구조 위에서 "리뉴얼 수준의 정리"를 하면 같은 결과를 더 빨리, 팀이 계속 쓰는 상태로 얻는다.

## 4. 2027 통합을 위해 남은 기간(10주)에 할 일 — 제안

### A. 기반 정리 (11월 전반)
1. 규칙을 한 곳에 — 회사 식별·채널 분류·도입일·매출 집계 기준을 코드 한 폴더에 모으고 전 화면이 그걸 쓰게
2. 데이터 건강 화면 — 매일 자동 점검(미연결 리드, 중복 의심 고객, 도입일 없음, 청구서 중복 등)을 목록으로 보여주고 바로 고치기
3. 죽은 모듈 결정 — 사이트 트래킹은 홈페이지에 설치해 살릴지, 미팅·납부관리는 뺄지
4. 큰 화면 쪼개기, 일회성 스크립트 보관 (기능 변화 없음)

### B. 시트를 대체할 입력 (11월 후반 ~ 12월)
5. **시트 업로드 화면** — 매출·고객·청구서 파일을 팀이 직접 올리고 비교 결과를 보고 반영 (지금은 개발자가 터미널에서 실행)
6. **매출 현황 직접 입력 완성** — 2027년부터는 시트 없이 CRM 에서 현장·서비스·월 금액을 바로 입력. 청구서는 매출에서 자동 생성 초안
7. **사용자 정의 모음(컬렉션)** — 시트의 "중요 현장", "효성(체감온도계)" 탭처럼, 사용자가 임의의 기준으로 현장·고객·리드를 묶고 그 모음에만 필요한 항목(열)을 추가해 같이 관리. 자유롭게 쓰되 원본 데이터(고객·현장·매출)와 연결돼 나중에 분석에 쓸 수 있게
   - 예: "효성 체감온도계" 모음 = 현장 N개 + 추가 항목(설치일, 온도계 수량, 담당자) + 메모
   - 모음별 합계(매출·청구·미납)를 자동으로 보여주고, 내보내기(엑셀) 지원
8. **견적서 고도화 + 매출 연동** — 현재 견적서는 품목표만 있어 쓰이지 않음. 필요한 것:
   - 리드/고객/현장에 붙는 견적서, 버전 관리, PDF/이메일 발송, 단가표 연동, 할인·옵션
   - 견적 → 수주 시 프로젝트(현장)·서비스·과금 조건 자동 생성 → 월 매출 예정 자동 생성 → 청구서 초안
   - 이러면 견적 금액 vs 실제 매출, 견적 전환율, 담당자별 수주율 같은 분석이 가능

### C. 마감 (12월 후반)
9. 2026년 데이터 최종 대조(시트 vs CRM), 팀 교육, 2027-01 부터 시트 입력 중단

## 5. 마케팅팀과 정할 것
1. 2027년에 시트에서 CRM 으로 옮길 입력은 무엇인가 (매출 현황, 고객 LIST, 매입매출, 미납, 중요 현장, 카메라 반출, 보증금 …)
2. 각 입력의 "원본"을 누가 어디에 입력하는가 (경영지원/세일즈/마케팅)
3. 사용자 정의 모음(컬렉션)에 필요한 기준·항목 예시 3개
4. 견적서에서 꼭 필요한 기능 순위 (PDF, 발송, 단가표, 버전, 수주 전환)
5. 안 쓰는 모듈 처리 (사이트 트래킹 설치 여부, 미팅·납부관리·VoC 유지 여부)
6. 마케팅 지표 정의 확정 (CVR=도입률, 사이트 전환율, ROAS 기준) — 7월 METRICS.md 초안 기준
